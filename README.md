# humanwrite

Turn a **human-written rough draft** into a final assignment draft that

1. reads as *that student's own* polished version of their rough work (not a
   new essay), and
2. passes a quantitative "human-likeness" gate against the rough draft, so
   AI-writing detectors (Copyleaks, ZeroGPT, etc.) have nothing to flag.

Every sentence of the final draft is generated by a **local LLM endpoint** —
never by the orchestrating agent, so the token distribution is the local
model's, not the writing assistant's.

---

## How to use it

### 1. Get the four inputs

| Input | What it is |
| --- | --- |
| **rough draft** | the student's own draft. This is the anchor, voice, structure, mistakes, and anchors all come from it. |
| **requirements** | what the assignment asks for (page/paragraph count, MLA, citations, …). |
| **notes** | the source material **as notes and short quotes**. Not the full book. |
| **guidelines** | course-specific writing rules. |

The source can be big, with a 204,800-token endpoint window the pipeline has
**no notes cap by default** (`gate.max_notes_words: 0` = unlimited). Set that
key to a word count to re-enable a cap on smaller endpoints.

### 2. Point it at your LLM endpoint

The default config (`humanwrite/config.yaml`) targets the local llama-swap /
OpenAI-compatible server:

```yaml
endpoint: http://10.60.50.11:9292/v1
model: Qwen3.8-27B
```

Override per-run with `--endpoint` / `--model`, or edit `config.yaml`. Any
OpenAI-compatible server (vLLM, llama-server, …) works, `api_style: auto`
handles both `/chat/completions` and llama's `/api/chat`.

> **Thinking models:** the endpoint model is a reasoning model. `max_tokens`
> defaults to 65536 so its thinking budget + content both fit. If you use a
> model that returns empty content by exhausting the budget on reasoning,
> either raise `sampling.max_tokens` or set `extra_body:
> {chat_template_kwargs: {enable_thinking: false}}` in `config.yaml`.

### 3. Run it

From the repo root:

```bash
python -m humanwrite.ingest \
  --rough  path/to/rough-draft.md \
  --requirements path/to/requirements.md \
  --notes  path/to/notes.md \
  --guidelines path/to/guidelines.md \
  --out out/final.md
```

Try it with the bundled samples:

```bash
python -m humanwrite.ingest \
  --rough  humanwrite/examples/rough_sample.md \
  --requirements humanwrite/examples/requirements_sample.md \
  --notes  humanwrite/examples/notes_sample.md \
  --guidelines humanwrite/examples/guidelines_sample.md \
  --out out/final.md
```

### 4. Read the report

Everything is written next to `--out`:

```text
out/
  final.md           # the final draft (all the prose is the model's)
  report.md          # per-metric gate results, side-by-side profiles, iteration log
  author_profile.json# measured stats of the rough draft
  candidate.md       # the best of the N generated candidates
  candidates/        # every candidate, numbered
  humanized.md       # after the de-AI pass
  constrained.md     # after pulling back toward the rough draft
```

**Exit codes:** `0` gate passed · `3` gate failed (see `report.md` for which
metrics) · `2` bad input / endpoint failure / notes too long · `130`
interrupted.

---

## What it does (the four steps)

Run as one command, but each step is a real stage:

1. **Profile + generate candidates.** Measures the rough draft (FK grade,
   sentence length, TTR, contraction rate, structure, error slips, opinions)
   into `author_profile.json`. The local model then writes `N` candidate
   drafts *in the student's voice* (default 3). Each is scored on tell-hits,
   metric deltas vs the rough draft, anchor preservation, and length; the best
   wins.
2. **Humanizer pass.** The winner goes through the local model with the
   AI-tell list; the model strips the tells with wording-only edits →
   `humanized.md`.
3. **Constrain pass.** The model pulls the draft back toward the rough draft:
   same sections in the same order, keep ≥ `anchor_min` of the sentences,
   re-introduce a small error budget, keep section lengths in proportion, drop
   any AI vocabulary → `constrained.md`.
4. **Gate.** `final.md` is compared against the rough draft on a fixed set of
   metrics. On failure, up to 3 targeted repair passes (each told only which
   checks failed) go through the model, then re-gate.

## How the gate decides "human enough"

The core idea: the final draft should sit in the **same statistical band as the
student's own rough draft**, so a detector comparing "this writer" sees no
anomaly. All thresholds live in `config.yaml` under `gate:`.

| Check | Passes when |
| --- | --- |
| FK grade | within ± `fk_tolerance` (2.0) of the rough draft |
| Mean sentence length | ratio in `[0.80, 1.25]` |
| TTR | ratio in `[0.85, 1.15]` |
| Contraction rate /100w | relative diff ≤ 0.50 (absolute ≤ 1.0 when the rate is low) |
| Tell scan | **0** hits (19 patterns, T01–T19) |
| Anchor preservation | ≥ `anchor_min` (0.30) of final sentences identical/near-identical (token Jaccard ≥ 0.85) to a rough-draft sentence |
| Length | word count in `[0.9, 1.5]`× the rough draft |

Reported but not gating: sentence-length CoV, passive rate, Flesch ease,
section-proportion deviation.

**The tell scan** (`tell_scan.py`, list in `references/ai_tells.md`) catches the
linguistic fingerprints of AI text: "not just X but Y", staged run-ups,
dramatic one-line closers, forced rule-of-three, em-dash connectors, stacked
qualifiers, AI vocabulary ("delve", "landscape", "tapestry", "leverage", …),
-ing riders, "serves as", vague authority, "in conclusion" closers, heading
restatement, decorative bold / Title-Case headings, curly quotes, chatbot
residue, hedging, and re-explaining. Vocabulary and the repeated-opening
threshold are config-driven. Repeated openings (T05) only flag an opener reused
7+ times, a few "That…" sentences is normal student voice, not a tell.

## Configuration

Every tunable is in `humanwrite/config.yaml` (merged over built-in defaults):

- **Endpoint**, `endpoint`, `model`, `api_key`, `api_style`
  (`auto` | `openai` | `llama`), `timeout_seconds`, `max_retries`,
  `extra_body` (merged verbatim into each request body).
- **`sampling`**, `temperature`, `top_p`, `presence_penalty`, `n_candidates`,
  `max_tokens`.
- **`gate`**, all the tolerances above plus `max_repair_iterations`,
  `max_notes_words` (0 = unlimited), `anchor_min`, `anchor_jaccard_min`.
- **`constrain`**, `section_proportion_tolerance`,
  `error_budget_per_500_words`, `humanizer_length_tolerance`.
- **`tell_scan`**, `repeated_opening_min`, `vocabulary`, `ing_riders`,
  `extra_words`, `disabled_patterns`.

## Rules the pipeline enforces

- **The agent never writes the prose.** All generation goes through the local
  endpoint. If the gate fails, the fix is another model repair pass, not a
  manual edit of the text.
- **Notes are uncapped by default** (`max_notes_words: 0`), the 204,800-token
  window holds the full source material. Set `gate.max_notes_words` to a word
  count to re-enable a cap on smaller endpoints.
- **The endpoint is slow** and may share one concurrency slot with whatever
  else is running on the machine; a full run takes a while and 429s are retried
  (30 s backoff) rather than failed. Don't parallelize endpoint calls.

## Standalone steps (optional)

Each stage is also runnable on its own:

```bash
python -m humanwrite.profile    --rough rough.md --out author_profile.json
python -m humanwrite.tell_scan  draft.md
python -m humanwrite.humanizer  --draft candidate.md --out humanized.md
python -m humanwrite.constrain  --draft humanized.md --rough rough.md \
                                --profile author_profile.json --out constrained.md
```

## Layout

```text
humanwrite/
  ingest.py        # CLI entry point + pipeline driver
  pipeline.py      # the four steps, gate loop, report
  profile.py       # author profile from the rough draft
  metrics.py       # readability/structure stats (FK, MSL, TTR, …)
  gate.py          # final-vs-rough comparison + anchor preservation
  tell_scan.py     # AI-tell scanner (T01–T19)
  humanizer.py     # pass 2: de-AI rewrite
  constrain.py     # pass 3: pull back toward the rough draft
  llm.py           # OpenAI/llama endpoint client
  config.py        # config loader (stdlib YAML subset)
  config.yaml      # every tunable
  references/      # ai_tells.md, prompts.md
  examples/        # sample inputs
  tests/           # pytest suite
```
